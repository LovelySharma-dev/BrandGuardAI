# Target Users, Jobs to Be Done, Pain Points

**Label note:** Personas below are **proposed** archetypes for product design. They are not based on conducted interviews unless the team later attaches interview notes.

## Primary users

### 1. Content creator / marketer

| | |
| --- | --- |
| **Job** | Ship channel-ready copy without triggering a late brand/legal rewrite |
| **Pain** | Guidelines are long; chatbot feedback is vague; corrections change the campaign angle |
| **Success** | Clear findings with sources; suggestions that keep the message goal; fast revise loop |

### 2. Brand / communications reviewer

| | |
| --- | --- |
| **Job** | Approve or reject content with consistent standards and a defensible rationale |
| **Pain** | Tickets lack context; same mistakes recur; unclear which guideline version applied |
| **Success** | Structured findings, evidence links, explicit workflow states, audit history |

### 3. Brand knowledge owner (guidelines / facts curator)

| | |
| --- | --- |
| **Job** | Keep approved facts, terms, claims policies, and assets current |
| **Pain** | PDFs drift; reviewers invent local folklore; AI tools cite outdated pages |
| **Success** | Versioned knowledge base; analytics showing unclear or frequently violated rules |

### 4. Compliance / legal stakeholder (secondary in MVP)

| | |
| --- | --- |
| **Job** | Reduce unsupported promotional claims reaching publication |
| **Pain** | Absolute claims and missing disclaimers arrive too late |
| **Success** | Claim policy flags with evidence status, not silent auto-block by model opinion |

## Organisational context (proposed)

Typical demo org: a product company with:

- a brand style guide (PDF/Markdown)
- an approved product-fact sheet
- a terminology list (preferred / banned)
- a promotional-claims policy (absolute language, comparative claims, regulated category notes)
- optional logo/lockup assets and colour tokens

**Assumption A6:** Demo content is fictional and labelled as such; no real customer PII.

## Jobs-to-be-done map

| When… | I want to… | So I can… |
| --- | --- | --- |
| I finish a draft | run a brand-governance review | know what is blocked vs. needs human judgment |
| I see a finding | open the supporting source or evidence gap | trust or challenge the result |
| I accept a suggestion | compare versions and keep my intent | revise without starting over |
| I am a reviewer | approve/reject with a recorded reason | prove who decided what, on which guideline version |
| I own guidelines | see recurring violations and low-clarity rules | improve the source of truth, not only punish authors |

## Explicit non-users (MVP)

- Consumer social listening / trademark watch teams (different problem; see trademark watch vendors)
- Fully automated publish-to-CMS without humans
- Agencies needing multi-client marketplace billing in Round 2
